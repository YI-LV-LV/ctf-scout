# ctf-scout 使用文档

## 1. 简介

ctf-scout 是一个面向授权 CTF 比赛、靶场和自有资产的自动化漏洞侦察智能体。它把端口扫描、服务识别、Web 指纹、敏感路径枚举、信息泄露检查和少量低风险主动验证组织成一条可自动追加任务的流水线，并输出 Markdown、JSON 与 HTML 报告。

适用范围：

- CTF Web / Misc / 内网靶场
- 自建漏洞练习环境
- 你拥有明确授权的安全测试

不适用范围：

- 未授权的公网资产
- 生产环境的高风险验证
- 需要 exploit、提权、横向移动的完整渗透流程

## 2. 环境与安装

环境要求：

- Python 3.10+
- 标准库即可运行，无第三方依赖

源码运行：

```bash
cd ctf-scout
python -m ctf_scout --help
```

安装为命令：

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -e .
ctf-scout --help
```

## 3. 目标格式

支持以下写法：

| 写法 | 解析结果 |
| --- | --- |
| `10.10.10.5` | `http://10.10.10.5:80` |
| `10.10.10.5:8080` | `http://10.10.10.5:8080` |
| `https://target.ctf.com` | `https://target.ctf.com:443` |
| `http://10.10.10.5/app` | 以 `/app` 为基准路径探测主端口 |
| `http://10.10.10.5:8080/api?x=1` | 保留路径与查询串作为入口 |

说明：

- 未写协议时默认使用 `http`。
- 使用 URL 形式时，基准路径只应用于目标端口；扫描到的其他端口从 `/` 开始探测。
- 暂不支持 IPv6。
- 公网地址必须额外传入 `--authorized`。

## 4. 扫描流程

一次完整扫描按以下顺序推进：

1. **端口扫描**：默认扫描 57 个常见端口，或使用 `--ports` / `--full` 指定范围。
2. **服务识别**：连接开放端口抓取 Banner，识别 HTTP/HTTPS、SSH、MySQL、Redis、SMB、Docker 等服务。
3. **Web 入口探测**：抓取首页，识别标题、响应头、Cookie、表单、链接、注释与技术栈。
4. **敏感路径枚举**：并发探测 61 条常见路径，跳过软 404 与整站 401/403 页面。
5. **robots.txt 跟进**：自动访问 Disallow/Allow 中的隐藏路径。
6. **被动检查**：安全响应头、Cookie、目录浏览、默认页、调试堆栈、HTML 注释、flag 格式。
7. **技术栈定向检查**：WordPress、Spring Boot、Swagger/OpenAPI、Jenkins、Nacos、Elasticsearch 等。
8. **主动验证（可选）**：SQLi、XSS、LFI、开放重定向、CORS、危险方法。
9. **服务风险汇总（可选）**：FTP 匿名、Redis、Docker、Memcached、Elasticsearch、CouchDB。
10. **分析收尾**：攻击路径排序、风险评分、建议命令、报告生成。

智能体采用任务队列模式：某个阶段发现新的 Web 入口或技术栈时，会动态追加后续任务。

## 5. 被动模式与主动模式

默认是被动模式，只做读取和指纹识别。

启用主动模式：

```bash
python -m ctf_scout scan http://10.10.10.5:8080 --active
```

主动模式会增加：

- 参数追加单引号，观察 SQL 报错特征
- 参数注入 SVG 标记，观察是否原样回显
- 参数注入路径穿越，检查系统文件特征
- 参数注入外部 URL，检查开放重定向
- 带 Origin 的 CORS 请求
- OPTIONS 方法检查
- Redis `PING`、Docker `/version`、ES `/_cat/indices`、Memcached `stats`、CouchDB `/_all_dbs`
- FTP 匿名登录

这些请求均为只读或低风险操作，不会写入目标数据，也不会执行系统命令。

## 6. 参数详解

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `target` | 必填 | 目标主机、`host:port` 或 URL |
| `--ports` | 常见端口 | 逗号或范围，如 `80,443,8000-9000` |
| `--full` | 关闭 | 扫描 1-65535 |
| `--timeout` | `8` | HTTP 请求超时秒数 |
| `--connect-timeout` | `0.7` | TCP 连接超时秒数 |
| `--threads` | `200` | 端口扫描并发数，最大 512 |
| `--active` | 关闭 | 启用低风险主动验证 |
| `--authorized` | 关闭 | 确认公网目标测试授权 |
| `--llm` | 关闭 | 启用 LLM 辅助分析 |
| `--format` | `all` | `all` / `md` / `json` / `html` / `none` |
| `--output` | `reports` | 报告输出目录 |
| `--no-color` | 关闭 | 禁用 ANSI 颜色 |
| `--quiet` | 关闭 | 只输出最终摘要 |
| `--max-steps` | `1000` | 智能体最大任务步数 |

参数校验失败或公网目标未授权时返回退出码 `2`。

## 7. 输出与报告

控制台会输出：

- 目标解析结果与授权范围
- 每个阶段的任务进度
- 开放端口与服务指纹
- 按严重度排序的发现摘要
- 推荐攻击路径
- 建议验证命令（仅打印，不自动执行）

报告默认写入：

```text
reports/<host>_<port>_<YYYYmmdd_HHMMSS>.md
reports/<host>_<port>_<YYYYmmdd_HHMMSS>.json
reports/<host>_<port>_<YYYYmmdd_HHMMSS>.html
```

选择单一格式：

```bash
python -m ctf_scout scan 10.10.10.5 --format md
python -m ctf_scout scan 10.10.10.5 --format json
python -m ctf_scout scan 10.10.10.5 --format html
```

不写文件：

```bash
python -m ctf_scout scan 10.10.10.5 --format none
```

JSON 中包含：目标信息、端口、Web 指纹、表单、Finding、命中路径、攻击路径、建议命令、日志与 AI 分析。

## 8. LLM 辅助分析

启用后，工具会把侦察摘要发送到配置的 OpenAI 兼容接口，返回中文分析建议。

```bash
# Windows PowerShell
$env:CTF_SCOUT_LLM_API_KEY="your-key"
$env:CTF_SCOUT_LLM_BASE_URL="https://api.openai.com/v1"
$env:CTF_SCOUT_LLM_MODEL="gpt-4o-mini"

python -m ctf_scout scan http://10.10.10.5:8080 --active --llm
```

支持的环境变量：

| 变量 | 说明 |
| --- | --- |
| `CTF_SCOUT_LLM_API_KEY` | API Key，也可回退到 `OPENAI_API_KEY` |
| `CTF_SCOUT_LLM_BASE_URL` | 接口根地址，默认 `https://api.openai.com/v1` |
| `CTF_SCOUT_LLM_MODEL` | 模型名，默认 `gpt-4o-mini` |

未配置 Key 时，`--llm` 会打印警告并跳过，不影响扫描与报告。

## 9. 典型场景

### 9.1 单个 Web 题

```bash
python -m ctf_scout scan http://10.10.10.5:8080 --active
```

重点关注：

- `.git/config`、`.env`、备份压缩包
- 后台入口、Swagger、Actuator
- SQLi / LFI / XSS 主动验证结果
- robots.txt 隐藏路径

### 9.2 未知服务的主机

```bash
python -m ctf_scout scan 10.10.10.5 --active
```

会先扫常见端口，再对每个 Web 端口分别建立入口，对非 Web 服务给出匿名/未授权验证。

### 9.3 全端口排查

```bash
python -m ctf_scout scan 10.10.10.5 --full --active --timeout 5
```

全端口扫描耗时取决于网络与主机防火墙，建议先使用常见端口确认方向。

### 9.4 HTTPS 自签名靶场

工具默认不校验证书，可直接扫描：

```bash
python -m ctf_scout scan https://10.10.10.5:8443 --active
```

### 9.5 子路径应用

```bash
python -m ctf_scout scan http://10.10.10.5/app --active
```

主端口会以 `/app` 为基准路径枚举；其他端口仍从 `/` 开始。

## 10. 结果解读

严重度：

| 等级 | 含义 |
| --- | --- |
| 严重 | 可直接获取敏感数据、flag、未授权访问或堆转储 |
| 高危 | 源码/配置泄露、SQLi、LFI、Actuator 配置暴露 |
| 中危 | 目录浏览、接口文档、phpinfo、反射 XSS |
| 低危 | 版本泄露、Cookie 属性、开放重定向、后台入口 |
| 信息 | robots、服务暴露、注释提示 |

风险评分为严重度加权和，最高 100，仅用于排序参考，不代表真实可利用性。

误报提示：

- SQLi 通过报错特征判断，可能被测试环境刻意构造。
- XSS 只检测原样回显，未验证浏览器上下文。
- LFI 只读取固定文件特征，未尝试写入或 RCE。
- 目录浏览、默认页、版本泄露属于配置问题，不一定是题目考点。

## 11. 常见问题

**Q：为什么没有发现任何端口？**

目标可能只允许特定来源访问，或端口不在默认列表。尝试 `--ports` 指定端口或 `--full`。

**Q：为什么 Web 路径枚举结果为 0？**

目标首页返回 401/403 时，工具会跳过逐路径探测以避免整站误报。可以手工确认是否存在公开接口后，使用自定义路径扩展字典。

**Q：全端口扫描很慢？**

可降低 `--connect-timeout`、提高 `--threads`，或先用 `--ports` 缩小范围。

**Q：报告里的命令会自动执行吗？**

不会。命令只作为人工验证建议输出，工具本身不执行 exploit、sqlmap 或任何外部程序。

**Q：扫描公网目标被拒绝？**

这是授权保护。确认已获得目标所有者的明确测试授权后，追加 `--authorized`。

**Q：可以扫描 IPv6 吗？**

当前版本不支持 IPv6。

**Q：报告可以公开分享吗？**

不可以直接公开。报告可能包含数据库口令、密钥、flag、内部路径等敏感信息。

## 12. 安全规范

- 只在授权范围内使用。
- 主动模式会发送测试请求，避免对生产系统使用。
- 不要修改目标数据、上传文件或执行命令。
- 不要将报告中的凭据用于范围外系统。
- 比赛结束后及时清理报告与本地缓存。
