# ctf-scout 架构说明

## 1. 设计目标

ctf-scout 的目标不是实现完整渗透框架，而是把 CTF 侦察阶段重复度最高的工作自动化，并保持：

- **零依赖**：只用 Python 标准库，方便在比赛环境、离线机器和容器中直接运行。
- **可解释**：每个发现都带目标、证据、建议与 CTF 思路，便于人工复核。
- **可扩展**：路径字典、检查逻辑、服务提示都以数据或独立函数组织。
- **有边界**：默认只读，主动验证需显式开启，公网目标需显式授权。

## 2. 总体结构

```text
CLI (cli.py)
  │
  ├── scope.py        目标解析 + 授权校验 + 端口解析
  │
  ├── Context         全局状态：端口、Web 入口、Finding、日志、选项
  │
  ├── Agent (agent.py)
  │     │
  │     └── 任务队列 dispatch
  │           ├── tools/recon.py      端口扫描、Banner、服务指纹
  │           ├── tools/web.py        Web 指纹、路径枚举、技术栈检查
  │           ├── tools/checks.py     被动泄露检查、主动验证
  │           └── tools/services.py   服务风险提示、未授权验证
  │
  ├── llm.py          可选 LLM 摘要分析
  │
  └── report.py       控制台摘要 + Markdown / JSON / HTML 报告
```

## 3. 执行流程

### 3.1 CLI 入口

`cli.run_scan()` 负责：

1. 启用 Windows ANSI 颜色。
2. 校验参数组合与数值范围。
3. 调用 `parse_target()` 解析目标。
4. 调用 `require_authorization()` 判断是否需要 `--authorized`。
5. 构造 `Context`。
6. 启动 `Agent.run()`。
7. 可选调用 `llm.review()`。
8. 调用 `write_reports()` 与 `print_summary()`。

### 3.2 智能体任务队列

`Agent` 使用 FIFO 队列，而不是固定阶段函数调用：

```python
queue = [("port_scan", None)]
while queue and steps < max_steps:
    kind, payload = queue.pop(0)
    handler(kind, payload)
```

特性：

- `enqueue()` 以 `(kind, str(payload))` 去重，避免重复任务。
- 任务执行失败只记录日志，不终止整体扫描。
- `max_steps` 防止异常目标导致任务无限膨胀。
- 后续任务由当前结果决定，例如：
  - 开放端口 → 服务识别
  - HTTP 服务 → Web 探测
  - Web 探测成功 → 路径枚举、被动检查、技术栈检查、主动验证
  - paths 命中或 robots → 技术栈检查或 robots 跟进

任务类型：

| 任务 | 作用 |
| --- | --- |
| `port_scan` | 扫描端口并派生服务识别任务 |
| `service_probe` | 抓 Banner、判断 HTTP、派生 Web 探测 |
| `http_probe` | 首页探测、指纹识别、派生枚举与检查 |
| `enum` | 敏感路径枚举、收集 robots |
| `robots` | 跟进 robots.txt 路径 |
| `passive` | 安全头、Cookie、目录浏览、注释、flag |
| `tech` | WordPress、Spring、Swagger、Jenkins、Nacos、ES |
| `active` | SQLi、XSS、LFI、重定向、CORS、方法 |

### 3.3 收尾

`Agent._finalize()`：

1. 生成非 Web 服务的被动提示。
2. 如果开启主动模式，执行服务未授权验证。
3. 按 Finding 标签生成攻击路径。
4. 生成建议验证命令。
5. 写入结束时间与统计日志。

## 4. 数据模型

### 4.1 Finding

统一表示所有发现：

```python
Finding(
    title="环境变量文件 .env 暴露",
    severity="critical",
    category="敏感路径",
    target="http://host/.env",
    evidence="HTTP 200 | text/plain | 54 字节 | ...",
    suggestion="读取数据库口令与 APP_KEY",
    ctf_hint="...",
    tags=["path", "exposure", "source-leak"],
)
```

`tags` 是攻击路径推理的关键输入，例如 `source-leak`、`sqli`、`lfi`、`unauth`、`admin`、`api`、`flag`。

### 4.2 Context

`Context` 是扫描期间唯一的可变状态容器：

- 目标信息与选项
- `open_ports: dict[int, ServiceInfo]`
- `web_targets: list[WebTarget]`
- `findings: list[Finding]`
- `discovered_paths`
- `attack_paths`、`commands`
- `ai_analysis`
- `logs`

`Context.add()` 负责去重：

- 标题 + 目标相同视为同一条发现。
- 新发现严重度更高时升级原发现。
- 证据追加合并，便于技术栈检查补充接口数量等信息。

### 4.3 WebTarget

保存一次首页探测的快照：

- URL、状态码、响应头、Cookie
- 标题、正文、长度
- 技术栈、表单、链接、脚本、HTML 注释
- `skip_enum`：Elasticsearch 等 API 入口跳过通用路径枚举

## 5. 模块职责

### 5.1 `scope.py`

- 解析 `host`、`host:port`、URL。
- 拒绝 IPv6、未指定地址、组播、广播。
- 用 `ipaddress` 判断本机/私网/链路本地。
- 公网目标要求 `--authorized`。
- 端口范围解析与校验。

### 5.2 `http.py`

- 基于 `urllib.request` 的轻量 HTTP 客户端。
- 手动处理最多 3 次重定向，且只跟随同主机。
- 自签名 HTTPS 不校验证书，适配靶场。
- 响应头统一小写，合并多条 `Set-Cookie`。
- `PageParser` 收集标题、表单、链接、脚本、meta generator、HTML 注释。
- 参数 URL 收集与替换，用于主动验证。

### 5.3 `tools/recon.py`

- `COMMON_PORTS`：57 个常见端口。
- `HTTP_PORTS` / `HTTPS_PORTS`：Web 端口提示。
- `PORT_SERVICES`：端口到服务名映射。
- `scan_ports()`：线程池 TCP connect 扫描。
- `probe_service()`：Banner 抓取、产品识别、HTTP 判断。

### 5.4 `tools/web.py`

- `probe_web()`：首页抓取与指纹识别。
- `detect_technologies()`：根据 Server、X-Powered-By、Cookie、正文、脚本判断技术栈。
- `enum_paths()`：
  - 先生成随机路径获取基线。
  - 整站 401/403 时跳过枚举。
  - 并发抓取路径字典。
  - 软 404 判断：状态码一致、长度接近或文本相似度高则丢弃。
  - 目录浏览特征升级为中危。
- `tech_checks()`：按技术栈做定向检查。
- `fetch_extra_paths()`：跟进 robots 路径。

### 5.5 `tools/checks.py`

- `passive_checks()`：安全头、版本泄露、Cookie、目录浏览、默认页、调试页、flag、注释。
- `active_checks()`：
  - CORS
  - OPTIONS
  - 报错 SQLi
  - 反射 XSS
  - LFI
  - 开放重定向
  - 跳过 `logout`、`delete` 等动作型参数

### 5.6 `tools/services.py`

- `SERVICE_HINTS`：端口到风险提示。
- `passive_service_findings()`：服务暴露信息。
- `active_service_checks()`：FTP/Redis/Docker/Memcached/ES/CouchDB 只读验证。

### 5.7 `report.py`

- `print_summary()`：控制台摘要。
- `render_markdown()`：报告 Markdown。
- `render_json()`：结构化数据，不包含 Web 正文，避免报告过大。
- `render_html()`：自包含深色主题页面。
- `write_reports()`：文件名 `<host>_<port>_<timestamp>`，按格式写出。

## 6. 去重与评分

### 6.1 去重

- 路径软 404：状态码、长度、文本相似度综合判断。
- 整站 401/403：跳过逐路径探测，避免全部命中。
- Finding：标题 + 目标去重，证据合并。
- robots 路径：已在字典中命中的路径不再重复跟进。

### 6.2 风险评分

```text
critical 50 / high 20 / medium 8 / low 2 / info 0
score = min(100, sum(weights))
```

评分只用于排序，不代表真实可利用性。

## 7. 安全设计

- **授权门禁**：公网目标必须 `--authorized`。
- **同主机重定向**：HTTP 客户端不跟随跨主机重定向。
- **只读验证**：所有主动检查均为 GET/HEAD/OPTIONS 或只读协议命令。
- **动作参数跳过**：含 `logout`、`delete`、`remove` 等名称的参数不做注入测试。
- **无 exploit**：不实现 RCE、上传 webshell、提权、爆破。
- **命令仅打印**：报告中的 sqlmap、git-dumper 等命令需人工执行。
- **敏感报告提示**：Markdown 与 HTML 均包含敏感信息警告。

## 8. 扩展点

### 8.1 新增敏感路径

编辑 `ctf_scout/wordlists.py`：

```python
PATHS["debug/"] = ("low", "调试目录暴露", "检查调试接口与堆栈信息。")
```

### 8.2 新增主动检查

在 `ctf_scout/tools/checks.py` 的 `active_checks()` 末尾追加：

```python
resp = request(url, timeout=min(timeout, 6.0))
if condition:
    findings.append(_finding(...))
```

### 8.3 新增服务提示

编辑 `ctf_scout/tools/services.py` 的 `SERVICE_HINTS`：

```python
9999: ("示例服务暴露", "info", "使用示例客户端连接并检查默认配置。")
```

### 8.4 新增技术栈检查

在 `ctf_scout/tools/web.py` 的 `tech_checks()` 中追加：

```python
if "NewTech" in techs:
    resp = request(urljoin(directory, "newtech/status"), timeout=min(timeout, 6.0))
    ...
```

### 8.5 新增报告格式

在 `report.py` 增加 `render_xxx()`，并在 `write_reports()` 的分支中注册扩展名。

## 9. 已知限制

- 规则驱动，无法理解复杂业务语义。
- 不维护登录态，不提交 POST 表单。
- 不解析 JavaScript 动态接口，只收集静态链接与脚本路径。
- 不做子域名枚举、目录递归爆破、参数 fuzz。
- 不支持 IPv6。
- 全端口扫描受目标网络与防火墙影响。
- HTML 报告中的 AI 分析按纯文本渲染，不解析 Markdown。

## 10. 未来可扩展方向

- 只读证据截图（需额外依赖，非当前零依赖目标）。
